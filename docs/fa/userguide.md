# 📘 راهنمای کاربر K-I Agent — فارسی

مرجع روزمره‌ی فارسی: دستورات اصلی، حافظه، سوارم، MCP، هوک‌ها و پیکربندی.
برای جزئیات کامل‌تر، [راهنمای کاربر انگلیسی](../USERGUIDE.md) مرجع اصلی است.

---

## 🧭 فلسفه‌ی استفاده

بعد از `init`، شما **مثل همیشه** با Claude Code یا Codex کار می‌کنید. سیستم هوک‌ها وظایف را به‌طور خودکار مسیریابی می‌کند، از الگوهای موفق یاد می‌گیرد و در پس‌زمینه هماهنگی عامل‌ها را مدیریت می‌کند. لازم نیست ۳۰۰+ ابزار MCP را حفظ باشید.

دو مدل اجرای اصلی:

| مدل | کِی استفاده کنید |
|-----|-------------------|
| **خودکار (پس‌زمینه)** | بعد از init؛ هوک‌ها تشخیص می‌دهند و تصمیم می‌گیرند |
| **دستوری (Explicit)** | وقتی می‌خواهید دقیقاً مشخص کنید چه اتفاقی بیفتد (دستورات و ابزارهای MCP) |

---

## ⚙️ دستورات اصلی CLI

```bash
k-i-agent init              # راه‌اندازی تعاملی (wizard) در پروژه فعلی
k-i-agent init --codex      # نسخه‌ی Codex (AGENTS.md می‌سازد به جای CLAUDE.md)
k-i-agent doctor            # بررسی سلامت: Node، npm، git، پیکربندی، حافظه، کلیدهای API
k-i-agent doctor --fix      # اجرای خودکار تعمیرات پیشنهادی
k-i-agent mcp start         # اجرای سرور MCP (stdio)
k-i-agent mcp tools         # لیست ابزارهای MCP در دسترس
k-i-agent mcp exec --tool system_health    # اجرای یک ابزار
k-i-agent swarm start --task "..."         # راه‌اندازی سوارم برای یک وظیفه
k-i-agent federation init / join / status  # فدراسیون بین ماشین‌ها
k-i-agent verify            # تأیید رمزنگاری‌شده‌ی بایت‌های نصب‌شده با witness manifest
k-i-agent eject             # تبدیل پروژه به یک toolkit مستقل با نام خودش (MetaHarness)
```

> 💡 برای لیست کامل و گزینه‌ها همیشه به `k-i-agent --help` اعتماد کنید.

## 🧠 حافظه (Memory)

حافظه قلب این سیستم است: تصمیم‌ها، یافته‌ها و زمینه‌های مفید **بین نشست‌ها** باقی می‌مانند.

### مفاهیم

- **AgentDB:** پایگاه حافظه‌ی برداری. جست‌وجو بر پایه **معنا** است (semantic)، نه فقط کلمه‌ی دقیق.
- **HNSW:** ایندکس برداری برای بازیابی سریع (میلی‌ثانیه‌ای حتی با میلیون‌ها بردار).
- **Namespace (فضای نام):** هر پروژه یا حوزه می‌تواند فضای حافظه‌ی جدا داشته باشد تا پروژه‌ها قاطی نشوند.

### کار با حافظه از طریق دستیار

به زبان ساده به دستیار بگویید:

> «به خاطر بسپار: در این پروژه از TypeScript strict و vitest استفاده می‌کنیم.»

و در نشست تازه:

> «پیکربندی تست این پروژه چیست؟ (از حافظه بخوان، حدس نزن.)»

### ابزارهای MCP حافظه

| ابزار | کاربرد |
|-------|-------|
| `memory_store` | ذخیره‌ی یک یادداشت/تصمیم/یافته |
| `memory_search` | جست‌وجوی معنایی در حافظه |
| `memory_get` / `memory_delete` | دسترسی/حذف دقیق |

> ⚠️ **نکته‌ی مهم:** حافظه فقط به‌اندازه‌ی **دقت اطلاعات ذخیره‌شده** مفید است. اگر اطلاعات کهنه یا اشتباه ذخیره کنید، دستیار به اشتباه استدلال می‌کند. گاه‌به‌گاه حافظه را بازبینی و تمیز کنید.

## 🐝 سوارم (Swarm)

سوارم = چند عامل متمرکز با یک هدف مشترک که با الگوی هماهنگی مشخص کار می‌کنند.

### توپولوژی‌ها

| توپولوژی | ساختار | مناسب برای |
|----------|--------|-------------|
| **سلسله‌مراتبی (Queen-led)** | یک هماهنگ‌کننده + کارکنان | اکثر کارهای توسعه — ساده و قابل‌پیش‌بینی |
| **مش (Mesh)** | همه با همه | تیم‌های هم‌سطح با وابستگی دوطرفه |
| **تطبیقی (Adaptive)** | داینامیک بر اساس کار | کارهای بزرگ و نامشخص |

### اجماع (Consensus)

سوارم برای تصمیمات گروهی از الگوریتم‌های اجماع (Raft، Gossip، Byzantine) استفاده می‌کند تا در وجود عاملِ کند یا نالایق، کار متوقف نشود.

### شروع یک سوارم

```bash
k-i-agent swarm start --task "ویژگی X را با تست پیاده کن"
```

یا از داخل دستیار، با درخواست عادی:

> «این ویژگی را با یک تیم کوچک: معمار، کدر، تستر و بازبین پیاده کن. خروجی هر مرحله را نشان بده.»

> 📌 **قانون طلایی:** تیم فقط وقتی که کار **قابل‌تقسیم** باشد. برای ویرایش دو خطی، یک عامل تکی بهتر است.

## 🔌 MCP — ابزارها

K-I Agent یک سرور MCP با صدها ابزار ارائه می‌دهد. گروه‌های اصلی:

| گروه | نمونه ابزار | چه می‌کند |
|------|--------------|-----------|
| **Core** | `system_health`, `status` | سلامت، وضعیت، کشف |
| **Memory** | `memory_store`, `memory_search` | ذخیره/بازیابی حافظه |
| **Swarm** | `swarm_init`, `agent_spawn`, `task_assign` | هماهنگی تیم‌ها |
| **Intelligence** | `learn_pattern`, `route_task` | یادگیری و مسیریابی |
| **DevTools** | `test_run`, `lint`, `diff_analyze` | ابزارهای توسعه |

### اتصال به دستیار

```bash
# Claude Code
claude mcp add k-i-agent -- npx --yes k-i-agent mcp start

# Codex
codex mcp add k-i-agent -- npx --yes k-i-agent mcp start

# Claude Desktop / Grok: همان ساختار در فایل mcp.json (به docs/fa/k-i-agent-explained.md فصل ۷-۹)
```

### خواندن نام ابزارها

ابزارها با پیشوند سرور صدا زده می‌شوند، مثل `mcp__k-i-agent__memory_store`. اگر نام ساده را نمی‌بینید، پیشوند را چک کنید.

## ⚡ هوک‌ها (Hooks) و کارکنان پس‌زمینه

هوک‌ها در لحظات کلیدی اجرا می‌شوند و هماهنگی خودکار را ممکن می‌سازند:

| هوک | زمان اجرا |
|-----|-----------|
| `session-start` | شروع نشست — بارگذاری زمینه و حافظه |
| `pre-task` | قبل از هر وظیفه — مسیریابی هوشمند |
| `post-task` | بعد از هر وظیفه — یادگیری از نتیجه |
| `route` | تصمیمِ «چه عاملی این کار را بکند» |

**۱۲ کارکنان پس‌زمینه** به‌طور خودکار فعال می‌شوند (مثلاً: بازرسی امنیتی، بهینه‌سازی، پیدا کردن شکاف تست، ...). بودجه و شرایط توقف آن‌ها را از پیش مشخص کنید.

## 🛡️ امنیت

- **AIDefence:** مسدودسازی تزریق پرامپت، شناسایی PII، اسکن ایمنی
- **اعتبارسنجی ورودی:** همه‌ی ورودی‌های عمومی با Zod اعتبارسنجی می‌شوند
- **جلوگیری از traversing مسیر و تزریق دستور:** ماژول‌های `PathValidator` و `SafeExecutor`
- **CVE remediation:** پلاگین `ruflo-security-audit` آسیب‌پذیری‌ها و CVEهای وابستگی‌ها را اسکن می‌کند
- **فدراسیون:** PII قبل از خروج حذف می‌شود؛ هر پیام امضا و قابل‌پایش است

> ⚠️ هیچ پلاگینی «اجرای امنِ هر ابزاری» را تضمین نمی‌کند. مجوزها را محدود، محیط را جدا و مرزهای تأیید را صریح نگه دارید.

## 🧾 پیکربندی

### فایل‌های اصلی

| فایل | نقش |
|------|-----|
| `.claude/` (در پروژه) | پیکربندی و حافظه‌ی پروژه‌ای |
| `CLAUDE.md` / `AGENTS.md` | دستورالعمل دائمی دستیار برای آن پروژه |
| متغیرهای محیطی | تنظیمات سطح بالا (بک‌اند حافظه، پورت MCP، log level و ...) |

### متغیرهای محیطی مهم (نمونه)

```bash
CLAUDE_FLOW_CONFIG=./claude-flow.config.json   # مسیر فایل پیکربندی
CLAUDE_FLOW_LOG_LEVEL=info                     # سطح لاگ: debug | info | warn | error
CLAUDE_FLOW_MEMORY_BACKEND=hybrid              # sqlite | agentdb | hybrid
CLAUDE_FLOW_MEMORY_PATH=./data/memory          # محل حافظه
CLAUDE_FLOW_MCP_PORT=3000                      # پورت MCP (در حالت HTTP)
```

> 💡 نام فنی متغیرهای محیطی (`CLAUDE_FLOW_*`) شناسه‌ی داخلی کد است؛ تغییر آن‌ها بدون تغییر کد، کار را از کار می‌اندازد.

## 🏥 عیب‌یابی سریع

| علامت | بررسی |
|-------|-------|
| `doctor` ردیفی قرمز است | دستور پیشنهادی همان ردیف را اجرا کنید؛ `doctor --fix` |
| ابزار MCP پیدا نمی‌شود | `mcp list` داخل دستیار؛ اسم سرور (k-i-agent) را چک کنید؛ ریستارت |
| حافظه خالی می‌ماند | مسیر `MEMORY_PATH` و بک‌اند (`hybrid`) را چک کنید؛ دایرکتوری باید writable باشد |
| سوارم گیر می‌کند | با `swarm status` بفرمایید؛ عامل‌های کند را kill کنید و با بودجه‌ی محدود‌تر شروع کنید |
| هزینه بالا می‌رود | `ruflo-cost-tracker` را فعال کنید؛ مسیریاب مدل را بررسی کنید (وظیفه‌ی ساده با مدل بزرگ) |
